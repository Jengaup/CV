Accessibility Statement

Last updated: October 25, 2026

Jose Alberto Jimenez is committed to making josealbertopr.com accessible to everyone, including people with disabilities. The target standard is WCAG 2.2 Level AA.

1. Conformance status

This site partially conforms to WCAG 2.2 Level AA. "Partially conforms" means that some content does not yet fully meet all success criteria.

2. Implemented accessibility features

  • Skip link: A "Skip to main content" link is available at the top of every page, allowing keyboard users to bypass the navigation.
  • Keyboard navigation: The site is fully navigable using a keyboard. Interactive elements (nav links, buttons, form fields) are reachable and operable with the Tab key.
  • Escape key: The mobile navigation menu can be dismissed with the Escape key. Focus returns to the hamburger button on close.
  • Semantic HTML: The page uses proper heading hierarchy (h1 → h2 → h3), <nav>, <main>, <header>, <footer>, and <section> landmarks with aria-labelledby.
  • Form accessibility: Contact form fields have visible labels, aria-required, aria-describedby error associations, and role="alert" on error messages for screen reader announcements.
  • Focus visible: Focus indicators are visible on all interactive elements. The language toggle button and navigation links have clear focus outlines.
  • Language attribute: The lang attribute on the <html> element updates dynamically when the user switches between English and Spanish.
  • Reduced motion: Animations and transitions are disabled for users who have enabled the "reduce motion" system preference (prefers-reduced-motion: reduce).
  • Decorative elements: SVG icons and decorative content carry aria-hidden="true" to prevent screen reader noise.
  • Color contrast: Text and interactive element colors are selected for sufficient contrast against background colors.
  • Responsive design: The layout adapts to screen widths down to 320px without horizontal scrolling.
  • Alt text: The avatar SVG has a descriptive aria-label. The LinkedIn and resume buttons have aria-label descriptions.

3. Known limitations

  • The scroll progress bar at the top of the portfolio page does not have an accessible equivalent for users who cannot perceive visual progress.
  • The cursor spotlight and 3D tilt animations are visual enhancements with no functional alternative; they are decorative and do not convey information.
  • The stat counter animations on the hero section are disabled for prefers-reduced-motion users but no static equivalent value is shown during the load phase before the counter resolves (it briefly shows "0").

4. Technical approach

This site is built with plain HTML, CSS, and JavaScript (no framework). There is no client-side routing, no lazy-loaded content that changes document structure unexpectedly, and no AJAX navigation that would confuse screen readers.

5. Feedback and contact

If you encounter any accessibility barriers on this site, please use the contact form with the subject "Accessibility Feedback". I will make reasonable efforts to respond within 10 business days and to address legitimate barriers.

6. Assessment approach

Accessibility has been assessed through:

  • Manual keyboard navigation testing.
  • Review against WCAG 2.2 AA success criteria.
  • Inspection of rendered markup and ARIA usage.

No automated testing service has performed a formal audit of this site.

Declaración de Accesibilidad

Última actualización: 25 de octubre de 2026

Jose Alberto Jimenez se compromete a que josealbertopr.com sea accesible para todas las personas, incluidas aquellas con discapacidades. El estándar objetivo es WCAG 2.2 Nivel AA.

1. Estado de conformidad

Este sitio cumple parcialmente con WCAG 2.2 Nivel AA. "Cumple parcialmente" significa que parte del contenido aún no satisface todos los criterios de éxito.

2. Características de accesibilidad implementadas

  • Enlace de salto: Un enlace "Saltar al contenido principal" aparece al inicio de cada página para que los usuarios de teclado puedan omitir la navegación.
  • Navegación por teclado: El sitio es completamente navegable con teclado. Los elementos interactivos son accesibles con la tecla Tab.
  • Tecla Escape: El menú de navegación móvil puede cerrarse con la tecla Escape. El foco regresa al botón hamburguesa al cerrarse.
  • HTML semántico: El sitio usa jerarquía de encabezados correcta, elementos <nav>, <main>, <header>, <footer> y <section> con aria-labelledby.
  • Accesibilidad del formulario: Los campos del formulario de contacto tienen etiquetas visibles, aria-required, asociaciones de error con aria-describedby y role="alert" en mensajes de error.
  • Foco visible: Los indicadores de foco son visibles en todos los elementos interactivos.
  • Atributo de idioma: El atributo lang del elemento <html> se actualiza dinámicamente al cambiar el idioma.
  • Movimiento reducido: Las animaciones se deshabilitan para usuarios con la preferencia de sistema "reducir movimiento" activada.
  • Elementos decorativos: Los íconos SVG y contenido decorativo tienen aria-hidden="true".
  • Contraste de color: Los colores de texto y elementos interactivos tienen contraste suficiente con el fondo.
  • Diseño responsivo: El diseño se adapta a anchos de pantalla desde 320px sin desplazamiento horizontal.

3. Limitaciones conocidas

  • La barra de progreso de desplazamiento no tiene un equivalente accesible para usuarios que no pueden percibir el progreso visual.
  • Las animaciones de cursor y tilt 3D son mejoras visuales decorativas que no transmiten información.
  • Los contadores de estadísticas muestran "0" brevemente antes de resolverse para usuarios sin movimiento reducido.

4. Enfoque técnico

Este sitio está construido con HTML, CSS y JavaScript puros, sin framework ni navegación AJAX que pueda confundir a los lectores de pantalla.

5. Comentarios y contacto

Si encuentra barreras de accesibilidad en este sitio, use el formulario de contacto con el asunto "Comentarios de Accesibilidad". Haré esfuerzos razonables para responder en un plazo de 10 días hábiles.

6. Método de evaluación

La accesibilidad ha sido evaluada mediante:

  • Pruebas manuales de navegación por teclado.
  • Revisión contra los criterios de éxito WCAG 2.2 AA.
  • Inspección del marcado renderizado y el uso de ARIA.

Ningún servicio de auditoría automatizado ha realizado una evaluación formal de este sitio.
